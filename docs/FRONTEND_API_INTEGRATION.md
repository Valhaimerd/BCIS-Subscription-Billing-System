# Frontend API Integration

All requests use `VITE_API_BASE_URL`, the shared success/error envelopes, JSON bodies, and the Bearer token held in session storage. TanStack Query owns remote cache state; successful mutations invalidate related list/detail keys so reloads prove persistence.

| Frontend view       | API methods and paths                                                                                | Inputs                                                                              | Roles                                                                                  |
| ------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Login/session       | `POST /auth/login`, `GET /auth/me`, `POST /auth/logout`                                              | Email/password; Bearer token                                                        | All accounts                                                                           |
| Dashboard           | `GET /students`, `/course-offerings`, `/grades` with `per_page=1`                                    | Authorization-scoped totals                                                         | Administrator, Staff, Instructor; Student receives shortcuts only                      |
| Profile             | Session data from `/auth/me`                                                                         | Linked `student_id` creates safe record links                                       | All                                                                                    |
| Users               | `GET`, `POST /users`; `PATCH`, `DELETE /users/{id}`; `GET /roles`                                    | Search, role/status, pagination; account form                                       | Administrator                                                                          |
| Roles               | `GET /roles`; `PATCH /roles/{id}`                                                                    | Search/status/pagination; editable name/description                                 | Administrator                                                                          |
| Students            | `GET`, `POST /students`; `GET`, `PATCH`, `DELETE /students/{id}`                                     | Search, program, year, status, sort, page; profile form                             | Administrator, Staff; scoped detail for Instructor/Student                             |
| Programs            | `GET`, `POST /programs`; `PATCH`, `DELETE /programs/{id}`                                            | Search/status/sort/page; program form                                               | Administrator, Staff                                                                   |
| Courses             | `GET`, `POST /courses`; `PATCH`, `DELETE /courses/{id}`                                              | Search/status/sort/page; course form                                                | Administrator, Staff                                                                   |
| Academic terms      | `GET`, `POST /academic-terms`; `PATCH`, `DELETE /academic-terms/{id}`                                | Search/term/status/sort/page; dates and lifecycle                                   | Administrator, Staff                                                                   |
| Course offerings    | `GET`, `POST /course-offerings`; `GET`, `PATCH`, `DELETE /course-offerings/{id}`; `GET /instructors` | Course, term, instructor, section, schedule, room, capacity, status                 | Administrator/Staff manage; Instructor/Student receive scoped reads                    |
| Offering roster     | `GET /course-offerings/{id}/students`                                                                | Status, search, sort, page                                                          | Administrator, Staff, assigned Instructor                                              |
| Enrollments         | `GET`, `POST /enrollments`; `PATCH`, `DELETE /enrollments/{id}`                                      | Search plus student/offering/term/instructor/status filters; enrollment form        | Administrator/Staff manage; scoped Instructor/Student reads                            |
| Student enrollments | `GET /students/{id}/enrollments`                                                                     | Status, sort, page                                                                  | Administrator, Staff, assigned Instructor, owning Student                              |
| Grades              | `GET`, `POST /grades`; `PATCH /grades/{id}`                                                          | Enrollment/student/offering/term/instructor/status filters; scores, remarks, status | Administrator/Staff manage; assigned Instructor edits; Student published reads         |
| Student grades      | `GET /students/{id}/grades`                                                                          | Status, sort, page                                                                  | Administrator, Staff, assigned Instructor, owning Student; Student sees published only |
| Academic record     | `GET /students/{id}/academic-record`                                                                 | Path student ID                                                                     | Administrator, Staff, owning Student                                                   |

Collection controls write URL query parameters, then the API performs filtering, sorting, authorization scope, and pagination. Forms display Zod client validation first and map backend field errors and safe conflict messages back to their controls. A `401` clears the session and returns to login; a `403` remains an access-denied state; `404`, validation, server, malformed-response, empty, and network states are visibly distinct and retryable where appropriate.
