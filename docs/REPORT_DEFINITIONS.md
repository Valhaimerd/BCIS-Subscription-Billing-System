# Report definitions and date basis

Reports answer the questions shown on the desktop **Reports** screen. All money values are stored and calculated in integer centavos; the UI formats pesos for display. `From` and `To` bound the activity period. `As of` excludes later financial postings and events where the report supports a historical view. The chosen filters are frozen with each preview. PDF and XLSX exports use that exact filter snapshot and include all matching authorized rows; print uses the visible preview page.

| Question / server kind                                   | Authoritative basis                                                                                                                                                              | Row source                                                     |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| How much did we collect? `COLLECTIONS`                   | Posted payments by payment date and method, grouped daily, weekly, monthly, or annually. Reversals count only if they had not happened by `As of`.                               | Payment and receipt records.                                   |
| Are collections keeping pace? `BILLING_COLLECTION`       | Finalized, non-void invoices by invoice date compared with posted payments by payment date. These are different event dates, so difference is not an unpaid-balance calculation. | Invoice and payment records.                                   |
| Which sources brought in revenue? `REVENUE`              | Payment allocations recorded by `As of`, grouped by plan, service, or collection area. Unallocated subscriber credit is excluded.                                                | Allocation, payment, and invoice records.                      |
| What was collected and remitted? `COLLECTOR_PERFORMANCE` | Route batches by batch date. Posted collection payments and recorded remittances are capped at `As of`; difference is remitted minus collected.                                  | Collection batches, batch accounts, payments, and remittances. |
| Which records changed? `ADJUSTMENTS_REVERSALS_VOIDS`     | Adjustments, payment reversals, and invoice voids dated within the period and no later than `As of`; each row has actor, timestamp, reason, and source invoice or payment ID.    | Immutable correction record and linked source.                 |
| Which balances are outstanding? `AR_AGING`               | Finalized, non-void invoices, dated adjustments, payment allocations, and subscriber credit at `As of`. Only nonzero balance services are included.                              | Oldest unpaid invoice and service account.                     |
| Which subscribers are on file? `SUBSCRIBER_MASTER`       | Current subscriber and service records. Date controls do not apply to this live register.                                                                                        | Subscriber profile by ID.                                      |
| What makes up one balance? `SUBSCRIBER_SOA`              | One subscriber’s dated ledger debits and credits within the period, ending no later than `As of`.                                                                                | Linked invoice or payment when available.                      |
| What actions did users perform? `USER_ACTIVITY`          | Audit events by actor and action within the period, through `As of`.                                                                                                             | Audit event counts.                                            |
| Who changed what and why? `AUDIT`                        | Immutable audit events within the period, through `As of`, including actor, timestamp, entity, reason, and recorded old/new values.                                              | Audit event and linked invoice or payment when present.        |

Aggregated chart bars show the visible preview page unless labeled as full snapshot totals. Open a record card to inspect its values. Invoice, payment, and subscriber source buttons appear only to roles with the corresponding read permission. The API enforces report and audit permissions independently of the UI.
